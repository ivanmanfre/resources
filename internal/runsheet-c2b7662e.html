AI Orientation Session — Call Runsheet

Buyer already runs real systems and wants to own the build. You direct, they drive. Spine of the call: diagnose → pick one → direct. You are NOT building live — you map their real setup, choose the first thing, and the written plan carries the detail.

Before the call

  • Confirm payment landed + they got the prep email (booking link + checklist).
  • They arrive with: main tools open, Claude Code installed if they could, and the one workflow eating the most of their week written down.
  • Run it on Zoom, not Meet — Zoom lets you "Request Remote Control" of their screen; Meet doesn't.
  • Have your demo skills loaded (see Skills).

Two questions that sort the call

1. "Is the data you'd automate/parse something you can't send to a cloud API?" → decides local-vs-cloud.
2. "What's the one workflow eating the most of your week?" → that's the first build.

Agenda (90 min)

~10 min1 · Frame & goal. What they do; what "own the process" means to them; the real trigger. Ask the two questions. Set the contract: we map + pick the first build, you leave with a written plan. You drive, I direct.
~20 min2 · Walk the real stack. They screen-share their tools/workflows. Call out where AI is worth pointing, and what to leave alone. Land on the 1–2 highest-leverage candidates.
~20 min3 · Foundations, tailored. Claude Code setup (repo + context, CLAUDE.md, claude --version ≥ 2.1.59 so auto-memory is on). Memory rung (see ladder). Where skills fit (demo one). Connect tools via MCP. Local-vs-cloud only if Q1 flagged sensitive data.
~25 min4 · The first build (the meat). Pick ONE: smallest win, biggest payback. Whiteboard trigger → steps → where the agent fits → where n8n orchestrates → where it breaks + guardrails. Build vs outsource per piece.
~15 min5 · Plan & next steps. Do-this-first / leave-this-alone. Learning path. Confirm what lands in the written plan + how they start this week.

Flexes by who shows up: a Derek (has hardware, knows some) → less "where AI helps," more local-vs-cloud + orchestration. A greener operator → more foundations, one simpler build.

Memory ladder (teach the rung they're on)

  • Crawl (native, ~zero effort): CLAUDE.md (write it or /init) + native auto-memory (on by default v2.1.59+, self-populates). /memory to view.
  • Walk: a recall-style skill that ranked-searches the markdown when files grow.
  • Run: Supabase + embeddings + daily ingests ONLY when memory must reach other systems, needs semantic search at scale, or a team shares it.
  • The $500 line: the most valuable thing you say is what NOT to build yet. Restraint is the deliverable.

Two machines → GitHub sync (e.g. office Mac + home PC)

He doesn't run git commands — he tells Claude Code in plain English and it does the git work. That's the whole lesson: he directs, Claude executes, he reads what it did. The setup lives in files, so it goes in a private GitHub repo and pulls onto either machine.

One-time, by hand (Claude can't do this part for him):

Sign into GitHub once per machine — do the gh login together (opens a browser, he approves). That's the only manual bit; everything after is natural language.

On the Mac — what he says to Claude Code:

  1. "Turn this project into a git repo, add a .gitignore that keeps my .env and API keys out, and push it to a new private GitHub repo called [name]." → Claude does the init, the .gitignore, the commit, creates the repo, pushes.
  2. "Write a CLAUDE.md for this project covering my stack, how I work, and the rules." → durable context that syncs with the repo.

On the PC — what he says:

  1. "Clone my private repo [name] and set it up here." → identical setup.
  2. To stay in sync after: "Pull my latest from GitHub" (or just "sync this with GitHub").
Gotchas — say these out loud:
  • Secrets never go to GitHub. When Claude sets up the repo, have it confirm the .env / keys are gitignored — glance that nothing with a key got committed.
  • The local model (Hermes) stays on the Mac — not in git, not on the PC. The PC uses Claude in the cloud, and can reach the Mac's model over the network if needed.
  • Auto-memory is per-machine (doesn't sync). Durable context goes in CLAUDE.md (which does sync). Don't promise his memory syncs across both.

The lesson under this: he never memorizes commands. He says what he wants in English, Claude runs it, he reads what it did. That's "owning it" without being a dev — and it's the thing that makes the $500 land.

Adding a local model (Hermes on the Mac)

Easier than it sounds, and — same as everything else — he can have Claude Code do it in plain English. Two newbie-friendly tools: Ollama (one app + one command) or LM Studio (full GUI, click to download and run). Ollama is the standard.

The whole thing (Ollama):

  1. Install Ollama (ollama.com) — or tell Claude Code "install Ollama on this Mac."
  2. "Pull the Hermes model and run a quick test" → Claude runs the pull and tests it. (Confirm the exact tag/size in the Ollama library; an 8B-class model runs almost anywhere.)
  3. It now serves a local API at http://localhost:11434 (OpenAI-compatible). That's the address n8n / his tools point at for the local-parse jobs.
Memory rule of thumb: the model has to fit in RAM. Mac Mini → an 8B-class model. Mac Studio (big unified memory) → 70B+. Don't pull a model bigger than the machine, or it crawls.

Do a 10-min dry run on your own Mac before Thursday: install Ollama, pull an 8B model, chat with it once. Then you're never lost live.

Skills — what to teach & install

Teach / share (general-purpose)

  • superpowers — the discipline pack (brainstorming, TDD, systematic-debugging, writing-plans, verification). Best live upgrade to how they work.
  • stochastic harnesses — stochastic-decision stochastic-audit stochastic-research stochastic-red-team. Great live demo — run one on a real decision they bring.
  • deep-research, plus teaching them to write their own skill for a workflow they repeat.
  • How it installs: a SKILL.md in ~/.claude/skills/<name>/ (user) or .claude/skills/ (project), or via the plugin marketplace (/plugin).
NEVER hand out (your moat, wired to YOUR infra): recall, brain, negotiate, proposals, clickup-searcher, leverage-radar, morning-triage, n8n-execs, bootstrap-client, usage-insights. Demo the concept ("I have a skill that searches my whole memory"), never the code.

Screen control (Zoom)

They share → you click Request Remote Control → they approve → you can drive. Momentary, revocable. Default to "they drive, you direct"; grab control only for a tricky setup step (protects the "you own it" framing).

Deliverable — the written plan (after)

  • Tools + setup order (what to install, in what sequence).
  • The first-build spec (the one workflow, its shape, build-vs-outsource per piece).
  • The memory + skills approach for their case.
  • Learning path — what to study, in what order.
  • The explicit "leave alone for now" list + the signals for when to climb each ladder.
