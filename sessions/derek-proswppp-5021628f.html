  • Business: SWPPP / stormwater compliance — inspections, reports, permits, plus a sales pipeline. Document-heavy and regulated, which is exactly why local parsing fits.

How the pieces fit

Local (Hermes on the Mac Studio) handles the cheap, private, bulk parsing of inspection docs, field notes, and permits. Claude handles reasoning, drafting, and agent decisions. n8n handles orchestration so it runs on triggers and schedules without you babysitting it.

The routing rule: sensitive or high-volume parsing goes local. Anything needing real reasoning or quality output goes to Claude. Don't push reasoning onto the local model; don't send private docs to the cloud.

Set up first (in order)

  1. Claude Code + a CLAUDE.md for how you actually work — your repo, tools, conventions, the "never do X" rules.
  2. Memory — you're on Claude Code's native auto-memory (on by default, v2.1.59+). Nothing to build yet; /memory to view it.
  3. Hermes on the Mac Studio via MLX (fastest on Apple silicon) or Ollama (easiest). pick on call
  4. Connect your tools to Claude through MCP — CRM, docs, calendar, your data.
  5. n8n orchestration — wire the local-vs-Claude routing so workflows run hands-off.

Learning path (what to study, in order)

  1. Claude Code basics + CLAUDE.md + /memory
  2. Writing your first skill for a workflow you repeat
  3. MCP — connecting Claude to your real tools
  4. n8n orchestration — triggers, routing, error handling
  5. Serving Hermes locally (MLX / Ollama) and calling it from n8n

Leave alone (for now)

  • No vector DB / "memory brain" yet. Native auto-memory covers you until memory must reach other systems, needs semantic search at scale, or a team shares it. Climb that ladder only then.
  • Don't force everything local. The Mac Studio earns its keep on private parsing; let Claude do the reasoning.
  • Don't build all the skills at once. One working build beats ten half-built ones.
